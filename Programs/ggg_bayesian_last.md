## 0. この文書の読み方

この文書は、`ggg_bayesian_last.py` を「先頭から順に読めば全体像が掴める」ように並べ直した引き継ぎ資料です。  
本文では、解析の目的、処理の流れ、実務上どこを見ればよいかを優先して説明します。  
数学的な定義やモデル比較の詳細は付録に分けています。物理計算の厳密な背景は修士論文に譲り、ここではコード理解に必要な範囲に絞ります。

## 1. 要旨

`ggg_bayesian_last.py` は、GGG の THz 透過スペクトルに物理モデルを当てはめ、ベイズ推定でパラメータ推定とモデル比較を行うスクリプトです。

このコードでやっていることは、大きく 3 つです。

1. 実験データ 10 本を読み込み、解析に使う形へ前処理する
2. 物理モデルから透過スペクトルを計算し、PyMC でパラメータを推定する
3. H-form と B-form を比較し、図と数値を保存する

この版の設計思想は明確で、**ポラリトン領域のスペクトル形状を最優先で合わせる**ことにあります。  
共振器領域は補助情報として扱い、スペクトル全体ではなく、**ピーク位置**と **FWHM** だけで弱く拘束します。

そのため、このコードを読むときは「全部の周波数帯を均等にフィットしている」と考えない方がよいです。  
中心にあるのは、ポラリトン領域を崩さずに、共振器領域から `eps_bg` と `gamma` に関する情報を追加する設計です。

## 2. 解析フロー

### 2.1 全体フロー

```text
+----------------------+
| 実験データを読む     |
| Excel 2 ファイル     |
+----------+-----------+
           |
           v
+----------------------+
| 前処理               |
| 正規化・領域分割     |
| ピーク位置/FWHM抽出  |
+----------+-----------+
           |
           v
+----------------------+
| 物理モデル計算       |
| H, chi, mu_r, 透過率 |
+----------+-----------+
           |
           v
+----------------------+
| ベイズモデル構築     |
| 事前分布 + 尤度      |
+----------+-----------+
           |
           v
+----------------------+
| SMC サンプリング     |
| H-form / B-form      |
+----------+-----------+
           |
           v
+----------------------+
| モデル比較・可視化   |
| Bayes factor, 図保存 |
+----------------------+
```

### 2.2 `main()` の処理順

`main()` を文章で追うと、流れは次の順です。

1. 実行条件と並列数を決める
2. v8 の参照パラメータを読む
3. 実験データを Excel から読み込む
4. 各データセットを正規化し、ピーク位置と FWHM を抽出する
5. H-form の PyMC モデルを作って SMC を回す
6. B-form の PyMC モデルを作って SMC を回す
7. ESS と Bayes factor で 2 モデルを比較する
8. 事後分布、事後予測スペクトル、感受率、エネルギー準位を保存する

### 2.3 モデル計算の内部フロー

1 回のモデル評価では、内部で次の計算が走ります。

```text
パラメータ
(g, a, B4, B6, eps_bg, gamma_1...gamma_7)
            |
            v
      get_hamiltonian()
            |
            v
 calculate_susceptibility()
            |
            v
   H-form: mu_r = 1 + chi
   B-form: mu_r = 1 / (1 - chi)
            |
            v
  calculate_transmission()
            |
            v
     予測透過スペクトル
            |
            v
   ピーク位置・FWHM 抽出
            |
            v
          尤度計算
```

## 3. このコードで何を推定しているか

推定対象は次の物理パラメータです。

| パラメータ | 役割 | スペクトルへの主な影響 |
| --- | --- | --- |
| `g` | g 因子 | 共鳴位置、準位差 |
| `a` | 感受率の強度スケール | 吸収の強さ |
| `B4` | 結晶場係数の 4 次項 | 準位構造 |
| `B6` | 結晶場係数の 6 次項 | 準位構造の微調整 |
| `eps_bg` | 背景誘電率 | Fabry-Perot 共振器モード |
| `gamma_1 ... gamma_7` | 緩和係数 | 線幅（＝FWHM）|

このうち、本文では次の理解で十分です。

- `g`, `B4`, `B6` は主にエネルギー準位と共鳴位置を決める
- `a` は吸収の強さを決める
- `eps_bg` は共振器ピークの位置に強く効く
- `gamma` はピーク幅に強く効く

`gamma` が 7 個ある理由や H-form / B-form の数式定義は、付録 A と付録 B にまとめます。

## 6. 解析設計の要点

### 6.1 一番大事な設計

このコードの要点は、**ポラリトン領域を主役にした尤度設計**です。

- ポラリトン領域は、透過スペクトル形状そのものを使って強く合わせる
- 共振器領域は、ピーク位置と FWHM だけを使う
- 背景領域は、弱い補助情報としてのみ使う

### 6.2 なぜこの設計にしているか

過去版では、共振器領域のスペクトル全体を強く当てに行くと、`a` が不自然に大きくなり、ポラリトン領域の再現が悪化しました。  
そのため v10 系では、共振器領域の役割を「全体形状を再現すること」ではなく、「`eps_bg` と `gamma` に補助的な制約を与えること」に限定しています。

### 6.3 読むときの注意

このコードは「どの領域も同じ重みで説明する標準的な一括フィット」ではありません。  
研究上の主張と実装上の主張が一致するように、意図的に非対称な尤度設計になっています。

## 7. 実務上の運用メモ

### 7.1 実行方法

```bash
python Programs/ggg_bayesian_last.py
```

- `DEBUG_MODE = True`
- `SMC_DRAWS` を減らす


### 7.2 よくある詰まりポイント

| 症状 | 確認すること |
| --- | --- |
| Excel が見つからない | `bayesian_inputs` の配置 |
| v8 参照 CSV が見つからない | `wls_v8_results_20260306_160250` の場所と名前 |
| 実行が重い | `DEBUG_MODE`, `SMC_DRAWS`, `SMC_CHAINS` |

### 7.3 改修するときの優先順位

1. 保存ファイル名やログなど、解析結果に影響しない部分から触る
2. `DEBUG_MODE` で処理の流れを確認する
3. `load_all_datasets()` の出力内容を把握する
4. `build_pymc_model()` の尤度設計を理解してから変更する
5. `MixedOutputModelOp.perform()` は最後に触る

`MixedOutputModelOp.perform()` は PyMC 中で何度も呼ばれる重い処理なので、小さな変更でも計算時間と結果の両方に効きます。

## 付録 A. パラメータの補足

### A.1 `gamma` が 7 個ある理由

`gamma` は単一の線幅ではなく、`gamma_1` から `gamma_7` までの 7 個を持ちます。  
これは、複数の遷移に同じ線幅を強制せず、遷移ごとの広がりを許すためです。

コードを追うときは、厳密な対応則よりも、まず「`gamma` 群が FWHM 側の拘束に効く」と理解しておけば十分です。

### A.2 `B6` を固定するオプション

`FIX_B6_ZERO = True` にすると、`B6` を 0 に固定して自由度を減らせます。  
情報量が足りず `B6` が不安定なときの運用上のスイッチです。

---

## 付録 B. H-form と B-form

H-form と B-form の違いは、磁気感受率 `chi` から比透磁率 `mu_r` をどう作るかです。

H-form:

```python
mu_r = 1.0 + chi
```

B-form:

```python
mu_r = 1.0 / (1.0 - chi)
```

この 2 つを同じデータ、同じ解析フローで別々に推定し、最後に比較します。

---

## 付録 C. 尤度の定義

本文では設計思想だけ述べましたが、実際の尤度の層は次の 3 本柱です。

1. ポラリトン領域: スペクトル形状の StudentT 尤度
2. 共振器領域: ピーク位置の StudentT 尤度
3. 共振器領域: FWHM の StudentT 尤度

必要に応じて背景領域の弱いスペクトル尤度も足します。

重要なのは、**共振器領域のスペクトル全体は主尤度にしていない**ことです。  
ここが過去版との最も大きな違いです。

---

## 付録 D. ベイズファクター

H-form と B-form の比較は、SMC で得た周辺尤度を使って行います。

```math
BF_{H/B}
= \frac{p(y \mid M_H)}{p(y \mid M_B)}
```

ここで `y` は観測データ、`M_H` と `M_B` は 2 つのモデルです。  
コードでは `compute_bayes_factor_smc()` が `log_marginal_likelihood` を使って `log_BF` と `log10_BF` を計算します。

実務上は次の順で読めば十分です。

1. `winner` がどちらかを見る
2. `log_BF` の符号で、どちらを支持しているかを見る
3. `abs(log_BF)` の大きさで、証拠の強さを見る

補足として、`comparison_ess` はサンプラー効率の比較であり、モデルの優劣そのものではありません。  
モデル選択は `comparison_bayes_factor` を優先して解釈します。

## 付録 E. 関数対応表

主要な関数だけ、役割をすぐ引ける形で残します。

| 種別 | 名前 | 役割 |
| --- | --- | --- |
| 実行設定 | `resolve_sampling_resources()` | 並列数を安全側に調整する |
| 物理モデル | `get_hamiltonian()` | `g`, `B4`, `B6`, `B` からハミルトニアンを作る |
| 物理モデル | `calculate_susceptibility()` | 感受率 `chi` を計算する |
| 物理モデル | `calculate_transmission()` | 比透磁率から透過率を計算する |
| 物理モデル | `calculate_transmission_for_params()` | パラメータ一式から透過スペクトルを返す |
| 前処理 | `load_all_datasets()` | 読み込み、正規化、ピーク抽出をまとめて行う |
| PyMC 連携 | `MixedOutputModelOp` | スペクトル、ピーク位置、FWHM を PyMC に渡す |
| 評価 | `compute_bayes_factor_smc()` | Bayes factor を計算する |
| ベイズモデル | `build_pymc_model()` | 事前分布と尤度を組み立てる |
| 実行入口 | `main()` | 全体を実行して保存する |
