# ISSUE-003: SMC 周辺尤度の抽出が保存形式依存で壊れやすい

## 背景

最新結果の `trace_H.pkl` と `trace_B.pkl` では、`log_marginal_likelihood` の保存形式が異なっていた。

- H-form: `(chains, stages)` 風の float 配列
- B-form: object 配列の中に履歴リスト

## 問題

この形式差を前提にしない実装だと、将来の PyMC 出力差分でベイズファクターが壊れる。

## ボトルネック

- raw 形式を毎回目視確認する必要がある
- 解析結果レビュー時の信頼性が下がる

## 解決策

- raw 値から「チェーンごとの履歴」を抽出する関数を用意する
- その履歴から「最終有限値のみ」を抜く
- ベイズファクター計算はその値だけで平均と標準偏差を出す
- float 配列と object 配列の両方を単体テストで固定する
