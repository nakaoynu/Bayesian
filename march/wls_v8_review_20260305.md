## 1. 概要

WLS (Weighted Least Squares) v8 による GGG (Gd₃Ga₅O₁₂) の混合フィッティング結果をレビューし、ベイズ推定との比較を行った。H-form と B-form の両方について、スピンハミルトニアンパラメータ (g, a, B4, B6) および線幅パラメータ (gamma_1〜gamma_7) を最適化している。

### 主要結果サマリー

| 指標 | H-form (WLS) | B-form (WLS) | H-form (Bayesian) | B-form (Bayesian) |
|------|-------------|-------------|-------------------|-------------------|
| 最適化成功 | ✅ True | ❌ False | ✅ 収束 | ✅ 収束 |
| chi2_reduced | 105.47 | 112.54 | N/A (WAIC使用) | N/A |
| AIC | -2556.34 | -2465.14 | - | - |
| BIC | -2484.43 | -2393.23 | - | - |

**結論**: H-form が AIC/BIC で優位だが、chi2_reduced が 105 と著しく高く（理想値≈1）、モデルまたは重み設定に深刻な問題がある。

## 2. 発見された問題点 (Issues)

### ISSUE 1: B-form 最適化の収束失敗 [重要度: 高]

**問題**: B-form の最適化が `success: false` で終了。最大関数評価回数 (`max_nfev=5000`) に到達して停止。

**コード箇所**: L562
```python
max_nfev=5000,
```

**影響**: B-form のパラメータ推定値が最適解に達していない可能性がある。

**修正方針**: 
- `max_nfev` を 15000 以上に増加
- `diff_step` の調整（現在 1e-8）
- global optimization (differential_evolution) によるマルチスタート初期化の検討

---

### ISSUE 2: chi2_reduced が異常に高い [重要度: 高]

**問題**: H-form の chi2_reduced = 105.47、B-form = 112.54。理想値は約1.0。

**原因分析**: `sigma = 0.01` (L404) が全データ点に一律に適用されており、実際のデータノイズレベルに比べて過度に小さい。

```python
sigma = 0.01  # L404
sigma_pol = sigma / np.sqrt(weight)  # weight=2.0 → sigma_pol = 0.00707
sigma_bg = sigma / np.sqrt(0.01)     # weight=0.01 → sigma_bg = 0.1
```

ポラリトン領域の sigma_pol ≈ 0.007 は、実際の測定ノイズ（~0.01-0.05）より小さく、残差を過大評価する。

**修正方針**:
- フィッティング後の残差ベースで sigma をリスケール (`sigma_rescaled = sigma * sqrt(chi2_reduced)`)
- またはデータのノイズレベルから適応的に sigma を推定

---

### ISSUE 3: gamma_3 の異常値 (H-form) [重要度: 高]

**問題**: H-form WLS で gamma_3 = 0.329 THz (329 GHz) と異常に大きい値が得られた。標準偏差 0.416 THz は値自体より大きく、物理的に無意味。

| パラメータ | WLS | Bayesian | 差異 |
|-----------|-----|----------|------|
| gamma_3 | 0.329 ± 0.416 THz | 0.021 ± 0.003 THz | **15倍の乖離** |

**原因**: WLS にはベイズ推定の階層事前分布（`log_gamma_mu`, `log_gamma_sd`）に相当する正則化がなく、gamma が上限 (0.5 THz) 近くまで発散。

**修正方針**: log(gamma) の L2 正則化ペナルティを残差関数に追加（ベイズの階層事前分布に相当）。

---

### ISSUE 4: gamma パラメータ間の近完全相関 [重要度: 中]

**問題**: 相関行列に |r| > 0.9 の相関対が複数存在し、パラメータの非識別性を示す。

**H-form の高相関ペア**:
- gamma_5 / gamma_6: r = -0.967
- gamma_6 / gamma_7: r = -0.968
- gamma_4 / gamma_7: r = 0.937

**B-form の高相関ペア**:
- gamma_4 / gamma_5: r = -0.938
- gamma_5 / gamma_7: r = -0.906
- gamma_3 / gamma_6: r = -0.915

**影響**: 高次の gamma パラメータがデータによって独立に制約されておらず、不確実性が過大評価される。

**修正方針**: 
- 相関が高いパラメータ対の警告出力を追加
- gamma_5, gamma_6, gamma_7 の結合（例: 共通値の使用）を検討

---

### ISSUE 5: 7T/9T でのピーク周波数誤差が壊滅的 [重要度: 高]

**問題**: H-form summary で 7T と 9T のピーク周波数誤差が 200 GHz 以上。

| 磁場 | 観測 peak (THz) | 予測 peak (THz) | 誤差 (GHz) |
|------|----------------|----------------|-----------|
| 7T | 0.5227 | 0.7523 | **229.6** |
| 9T | 0.5325 | 0.7572 | **224.7** |

**原因**: `compute_cavity_peak_info` が最も顕著なピークを抽出するが、反交差(anticrossing) 領域では観測と予測で異なるモードのピークを拾っている可能性が高い。

**修正方針**: ピーク比較ロジックを改善し、最近接ピークマッチングまたは周波数範囲の制限を導入。

---

### ISSUE 6: B4/B6 の制約不良 [重要度: 中]

**問題**: 結晶場パラメータの不確実性が値に比べて極端に大きい。

| パラメータ | WLS 値 ± std | Bayesian 値 ± std | 相対不確実性(WLS) |
|-----------|-------------|-------------------|-----------------|
| B4 (H) | 0.071 ± 0.316 | 0.010 ± 0.024 | **440%** |
| B6 (H) | -0.022 ± 0.480 | -0.000 ± 0.005 | **2170%** |
| B4 (B) | -0.072 ± 0.321 | -0.070 ± 0.011 | **446%** |
| B6 (B) | 0.011 ± 1.240 | -0.002 ± 0.003 | **11000%** |

**影響**: WLS ではこれらのパラメータは実質的に決定されていない。

**修正方針**: 相対不確実性 > 100% のパラメータに対して警告を出力。

---

### ISSUE 7: B-form eps_bg の異常に小さい不確実性 [重要度: 低]

**問題**: B-form の `eps_bg_std = 2.37e-06` は他のパラメータに比べて桁違いに小さく、数値的な問題（境界への収束、ヤコビアンの特異性）を示唆。

**修正方針**: ヤコビアンベースの不確実性推定の数値安定性を改善。

---

### ISSUE 8: CSV出力のフォーマットバグ [重要度: 低]

**問題**: `parameters_*.csv` の gamma 列に `np.float64(...)` 文字列が出力されている。

**コード箇所**: L1096付近
```python
list(result.x[5:12])  # np.float64型のまま
```

**修正方針**:
```python
[float(x) for x in result.x[5:12]]  # Python float に変換
```

---

### ISSUE 9: gamma 正則化の欠如 [重要度: 高]

**問題**: ベイズ推定では階層事前分布が gamma パラメータを制約するのに対し、WLS にはそのような正則化メカニズムがない。

**ベイズモデルの gamma 制約**:
```python
log_gamma_mu = numpyro.sample("log_gamma_mu", dist.Normal(-3.5, 1.0))
log_gamma_sd = numpyro.sample("log_gamma_sd", dist.HalfNormal(0.5))
log_gamma_raw = numpyro.sample("log_gamma_raw", dist.Normal(0, 1).expand([7]))
log_gamma = log_gamma_mu + log_gamma_sd * log_gamma_raw
```

これにより gamma は log-normal 分布に従い、極端な値が抑制される。

**修正方針**: 残差関数に L2 正則化項を追加:
```python
# gamma の log-normal 正則化
log_gamma = np.log(gamma_arr)
log_gamma_mean = np.mean(log_gamma)
gamma_penalty = lambda_gamma * np.sum((log_gamma - log_gamma_mean)**2)
```

---

### ISSUE 10: バックグラウンド残差の支配 [重要度: 低]

**問題**: バックグラウンド領域のデータ点数がポラリトン/FWHM 点より圧倒的に多く、コスト関数を支配する可能性。

**現状の重み設計**:
- background: weight = 0.01 (L357)
- polariton: weight = 2.0 (L360) 
- FWHM: weight = 1.0 (L364)

重みの効果は sigma で除算されるため、実効的にはバランスが取れているが、データ点数の不均衡は残る。

**修正方針**: 領域ごとの点数で正規化する重み設計を検討。

## 6. 実装予定の修正一覧

1. **gamma L2 正則化**: 残差関数に `lambda_gamma * sum((log(gamma) - mean(log(gamma)))^2)` を追加
2. **max_nfev 増加**: 5000 → 15000
3. **ピーク周波数比較の改善**: 最近接ピークマッチングの導入
4. **sigma リスケール**: フィッティング後に `sigma *= sqrt(chi2_reduced)` でリスケール
5. **パラメータ警告**: 相対不確実性 > 100% の場合に警告を出力
6. **CSV フォーマット修正**: `np.float64` → `float` 変換
